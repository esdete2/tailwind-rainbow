Add prefix coloring modes and configurable predefined collections for GitHub issue #14.

Build on completed baseline plan 20261023-104123-d-ops-2e8 and syntax compatibility plan 20261024-092359-d-ops-1rg. Use merged 0.3.0 commit 48499045515810ee551951a8bc6c4b5548a37c97 as the before-control.

Philip selected Tailwind documentation categories as the predefined collections, tailwindRainbow.mode as the mode setting, and simple collection arrays that replace a predefined definition or add a custom one. Fine-grained CSS-property groups, include/exclude objects and longer mode-setting names were rejected in dialogue. Collection membership and per-theme colors remain separate. Preserve existing highlighting by default.

## Acceptance criteria

- [ ] Add tailwindRainbow.mode with class (default/current behavior) and prefix values. In prefix mode each variant color stops after its colon. Explicit utility colors from base or collection rules and important-marker styles remain independent. Preserve multi-variant, arbitrary-selector and v3/v4 important syntax, exact UTF-16 ranges and configuration reloads.
- [ ] Ship readable predefined collections matching Tailwind documentation categories: layout, flexboxGrid, spacing, sizing, typography, backgrounds, borders, effects, filters, tables, transitionsAnimation, transforms, interactivity, svg and accessibility. Source-link and test their exact utility names and literal family patterns, covering v3/v4 syntax, valid negative families and grouped values. Follow v4 documentation category boundaries and document retained v3-only families and category differences. In particular, bare flex/grid are display utilities in layout. No Tailwind runtime dependency or project configuration execution is introduced; membership does not claim exhaustive validation of custom utility values.
- [ ] Add tailwindRainbow.collections as a name-to-string-array setting. Omitted names retain predefined contents; an existing name replaces its complete definition; a new name adds a collection; an empty array empties it. Entries accept exact class names and literal prefixes ending in -*, including multi-component and negative prefixes; embedded glob operators and regular expressions are unsupported. Compile/cache matching data on configuration changes. Add optional theme.collections colors/styles using the existing ClassConfig contract; merge settings overlays with registered themes and remove stale overrides on reload. Default collection styles remain empty.
- [ ] Preserve existing special/exact/wildcard base precedence and arbitrary-property behavior. Consult styled collections only when existing base lookup has no match. For overlapping styled collections, configured definitions are considered in user-written order before untouched predefined collections in documented category order. A disabled matching rule blocks lower-priority collection rules; unconfigured collection styles do not participate. Preserve independent variant fallback in class mode, public service methods and utility adapters.
- [ ] Add tests for mode behavior, collection replacement/addition/empty arrays, overlaps and disabled rules, literal pattern boundaries, negative classes, unknown/custom classes, source offsets and theme/configuration reloads. Keep ordinary-string exclusion and established regressions passing. Add targeted real VS Code checks and run editor checks against VS Code 1.96.0 and the installed editor. Pass strict and legacy suites, compilation, lint, formatting and package-content checks.
- [ ] Preserve prior benchmark reports and harnesses. Record matching before/after Node 24 and real VS Code measurements under benchmarks/collections. Preserve all six lexical/highlighting fingerprints with default settings, investigate material regressions, and separately measure enabled collections/prefix mode with explicit settings and sampling limitations. Document runnable examples, categories, matching/overlap precedence and coverage limits in the README and an Unreleased changelog entry. Preserve released 0.3.0 notes and its artifact; do not bump a version.

Create local branch feat/collections from merged main and commit locally. Do not push, merge, tag, publish, install into the normal editor profile, or post/close issue #14. Use the SDD CLI with explicit summaries and local mechanical validation; external LLM preflight remains skipped. Dependency-security maintenance and unrelated detection features remain deferred.
