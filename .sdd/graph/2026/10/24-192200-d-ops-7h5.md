Update the extension's development dependencies and make its build and verification toolchain reproducible while preserving VS Code 1.96 support and tokenizer behavior.

The completed syntax compatibility plan 20261024-092359-d-ops-1rg provides the correctness and performance comparison point. Registry and official compatibility checks show that several development tools are outdated, CI still selects Node 18, and the current lockfile resolves VS Code API types above the declared minimum editor version. The pinned packaging tool also fails under the current local Node 25 runtime. All declared npm dependencies are development dependencies; the extension package has no runtime npm dependencies.

Choose compatible releases rather than upgrading every package to its newest major. TypeScript ESLint 8.72.0 supports TypeScript below 6.1, so target TypeScript 6.0.3 rather than TypeScript 7. Use Node 24 LTS for development and CI, while retaining Node 20 API typings appropriate to the minimum editor. Keep the existing TypeScript module and JavaScript targets unless a verified compatibility requirement needs a documented adjustment.

## Acceptance criteria

- [ ] Remove unused Jest, ts-jest and the npm path package, plus redundant @types/glob. Update the remaining development tools to mutually compatible stable versions, targeting TypeScript 6.0.3, TypeScript ESLint 8.72.0, ESLint 10.13.0, VSCE 4.0.0, test-electron 3.1.0, Prettier 3.9.10, Glob 13.0.6 and Mocha 12.0.3, with compatible plugins and supporting packages. Resolve peer requirements and document any justified version holds or target adjustments.
- [ ] Specify Node 24 LTS and pin pnpm 10.33.0 for development and CI. Regenerate the lockfile and verify a frozen-lockfile installation. Update CI to run the strict suite, isolated editor checks and packaging with the supported toolchain. Keep the legacy Mocha suite available and repair runner compatibility where required. Do not install or replace global runtimes.
- [ ] Preserve engines.vscode at ^1.96.0, pin @types/vscode exactly to 1.96.0, and update Node 20 typings within that major. Make explicit ambient-type or other compiler configuration adjustments needed by TypeScript 6. Limit production source changes to necessary compatibility fixes and preserve public APIs and highlighting behavior.
- [ ] Pass the existing 142-test strict suite and 16-check real-host suite, compilation, lint and formatting. Run real-host checks against both VS Code 1.96.0 and the installed editor. Retain meaningful test coverage if tool APIs require adaptation, and document any verification limitation rather than claiming unexecuted CI results.
- [ ] Build a complete local VSIX under Node 24. Inspect its contents for the compiled extension modules and development-artifact exclusions. Record reproducible setup, test and build commands and any remaining packaging limitations.
- [ ] Preserve prior benchmark reports and harnesses. Verify all six lexical and highlighting output fingerprints with the updated compiler, and record fresh real-host performance against benchmarks/tailwind-syntax under matching conditions. Investigate material regressions. If Node timing reports are collected under Node 24, use a matching before-control or label them as a new runtime baseline; do not directly compare them to Node 25 timings as evidence of a toolchain speed change.

Continue on local branch sdd/2e8-measure-production-tokenizer. Commit locally without pushing or merging. Do not publish the VSIX or install it into the normal editor profile. Use the SDD CLI, explicit summaries and local mechanical validation; external LLM preflight remains skipped. GitHub feature requests and additional Tailwind features remain deferred.
