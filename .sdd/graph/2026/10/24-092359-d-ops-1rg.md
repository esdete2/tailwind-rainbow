Add a Tailwind v3/v4 compatibility matrix and fix important-modifier and parenthesized-value parsing.

The completed review-fix plan 20261023-190546-d-ops-981 provides the comparison point. Official Tailwind documentation and direct parser probes show two grammar gaps: v3 places important markers after variants (hover:!flex), while v4 recommends a suffix (hover:flex!); typed variable shorthand such as text-(length:--size) contains a colon that is not a variant separator. The earlier !hover:flex tests exercised an extension compatibility form rather than the documented v3 placement.

Support both documented syntaxes in one tokenizer without requiring version detection. Retain the extension's existing leading-before-variants form as explicitly labeled compatibility behavior. New variant palettes, namespace-aware theme resolution, CSS configuration discovery and @source inline class lists remain separate follow-ups; the matrix must identify these gaps without asserting complete Tailwind v4 support.

- [ ] Add a source-linked compatibility matrix distinguishing v3, v4.0 and later v4 additions, grammar support, default theme coverage and deferred features. Cover important placement, prefixes, variable shorthand, variant composition, new variants, dynamic values and CSS class-list contexts. Historical compatibility forms must be labeled separately from documented Tailwind syntax.
- [ ] Parse !flex, hover:!flex, flex! and hover:flex!, including multiple variants and prefixed class strings, with exact UTF-16 ranges. Important styling applies to the marker separately; utility lookup excludes the marker, and styled class fragments do not consume it. Tests cover enabled/disabled important, prefix and base rules, nonzero offsets and the existing final-prefix fallback when the base is unstyled.
- [ ] Colons inside parenthesized values are not split as variants. Preserve bracketed arbitrary values and properties, nested functions, quoted/escaped delimiters and literal exclamation marks inside protected values. Use the same theme lookup rules for parenthesized utilities as for corresponding bracketed utilities. No theme-category expansion is implied.
