Establish a reproducible performance baseline and regression contract for the current production tokenizer before rebuilding it in TypeScript.

The earlier prototype measured class regions supplied by a caller. It did not measure production context detection, theme lookup, range construction or overlap handling. The rebuild needs measurements of the existing implementation and executable expectations for the reported defects before implementation choices are assessed.

## Acceptance criteria

- [ ] Benchmark the unchanged production document-tokenization and themed-range paths with deterministic HTML, JSX/TSX and CSS fixtures, realistic sizes and a repeated-variant stress case. Record source and fixture fingerprints, environment, raw samples, medians, tail statistics and actual emitted range counts. Preserve file-size guards and identify any measurement limit explicitly.
- [ ] Add passing characterization tests for supported contexts and exact UTF-16 ranges, plus executable desired-behavior regressions for unrelated-string highlighting, commented CSS @apply, important-prefixed range overflow, the ignored enable setting, loss of API-registered themes on configuration changes and untitled-document highlighting.
- [ ] Identify known failures explicitly without turning their current incorrect results into assertions of correctness. Provide a strict regression command that fails until those expectations are met.
- [ ] Document repeatable baseline and comparison commands. Separate Node tests using a VS Code API test double from actual extension-host measurements; report their limits honestly.
- [ ] Keep production tokenizer, configuration, theme and decoration behavior unchanged during this baseline phase. Record a proposed TypeScript module split for context extraction, class scanning, theme resolution and range assembly, with durable comments explaining contracts and constraints. Defer the implementation until the baseline is reviewed.

## Scope

This phase adds measurement and tests. Prefix-only styling, category palettes, new framework support and the tokenizer rewrite remain subsequent work. Use the networkteam/sdd CLI for the project record; do not invoke its MCP server.
